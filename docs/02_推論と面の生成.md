# 02 推論と面の生成

対象: `generator/src/Logic/Derive.hs`、`Refute.hs`、`web/js/logic.js` の後半。
対応する授業の章: 第 5 章(再帰)、第 6 章(高階関数)、第 7 章(列挙型)。探索は Number Match の Solver と同じ考え方です。

## 推論規則を関数にする

DERIVE の規則は 2 つの式から結論を返す関数 `derive` です。パターンマッチで規則の形を書きます。

```haskell
mp a (Imp a' b) | a == a' = Just (MP, b)       -- A, A→B ⊢ B
mt (Not b) (Imp a b') | b == b' = Just (MT, Not a)   -- ¬B, A→B ⊢ ¬A
ds (Not a) (Or l r)
  | a == l = Just (DS, r)                          -- ¬A, A∨B ⊢ B
  | a == r = Just (DS, l)
```

タップの順序は問わないので、`both f` が `f x y` と `f y x` の両方を試します。∧I(A と B から A∧B)は無条件に許すと何でも作れてしまうので、「A∧B が Goal の部分式のときだけ」に限っています。⊥ は Goal が ⊥ のときだけです。

一致は構文上の完全一致です。`¬¬p` と `p` は意味は同じでも別の式として扱います。同値変形を規則に入れると判断が重くなるので、入れていません。

## 1 手と探索

`legalMoves` は、つながっている 2 枚の組すべてに `derive` を当てて、使える手と結果の Board を列挙します。∧E(A∧B を分ける)も 1 枚の手としてここに入ります。

最短手数 `par` は幅優先探索で求めます。深さ優先ではなく幅優先なのは、「最短」が欲しいからです。状態は Board の 16 要素で、訪問済みは `Data.Set` に入れます。

```haskell
bfs :: Int -> Prop -> Board -> Maybe [Move]
```

Number Match の Solver との違いは 2 つです。深さごとに全部の状態を広げること、そして Goal に届いた瞬間にその手順を返すことです。手順は探索の途中で逆順に積んでいき、見つかったときに `reverse` します。

## 面を前向きに作る

DERIVE の面は答えから作ります。前提をランダムに 1 つ選び、そこへ規則を 1 つずつ当てて結論を伸ばし、最後の結論を Goal にします。

```
前提 ¬q  --(MP: ¬q と ¬q→p)-->  p  --(MT: p は ¬¬p ではないので MP)-->  ...
```

この作り方なら、使った前提を全部 Board に置けば必ず Goal に届きます。`buildDerivation` がその鎖を作り、`placeBoard` が前提と邪魔タイルを 4×4 に置いて、幅優先探索で `par` を確かめます。邪魔タイルは「Goal と一致せず、Board 上のどの式とも 1 手で Goal を作らない」ものだけを選びます。

## 行き止まりを無くす

合体はタイルを消費するので、必要な前提を別の規則に使ってしまうと Goal に届かなくなることがあります。試作の面を調べると、初手の半分が行き止まりになる面がありました。これは「考えて選ぶ」より「運で外す」に近く、面白くありません。

そこで Stage 1〜10 の面は、**到達できるどの状態からも Goal に届く**ものだけを採用しています。判定は次の手順です。

1. `reachableStates` が、初期 Board から打てる手を全部たどって、到達できる状態を集める(Board は小さいので多くても数百)。
2. Goal を含む状態を「生きている」とし、「生きている状態に 1 手で行ける状態」も生きているとして広げる。増えなくなるまで繰り返す(不動点)。
3. 全部の状態が生きていれば、その面に行き止まりは無い。

```haskell
step live = Set.fromList [b | b <- states, reaches goal b || any (`Set.member` live) (map snd (legalMoves goal b))]
fix live  = let live' = step live in if live' == live then live else fix live'
```

Stage 11 以降は行き止まりを許しますが、初手の半分以上が行き止まりになる面は採りません。ゲーム側では、手を打つたびに `goalReachable`(JavaScript 版の幅優先探索)で届くかを調べ、届かなくなったら「この先 Goal に届かない … UNDO で戻ろう」と知らせます。UNDO は何手でもできますが、手数は数えたままなので、見極めの速さが Star に効きます。

## REFUTE の面

REFUTE は Number Match と同じく「全部消せる面」が要ります。ただし式のタイルをランダムに並べると、30 枚の面はほとんど解けません。矛盾する組が少なく、位置の条件も厳しいからです。

そこで空の格子に「同じ行か列で、間が空いている 2 マス」を選び、そこへ矛盾する 2 枚を置く、という手順を繰り返して面を作ります。置いた順の逆に消していけば必ず全消しできるので、解けることが構成から保証されます。そのうえで Number Match と同じ深さ優先探索(予算 3000、行が消える手を先に)でも解けることを確かめてから採用しています。斜めは行の縮約で位置が変わるため「置く筋道」には使いませんが、遊ぶ側は斜めも使えます。

語彙は Stage ごとにグループ分けし(リテラル、深さ 1、その否定、深さ 2)、重み付きで選びます。トートロジーと矛盾式は除きます(01 を参照)。
